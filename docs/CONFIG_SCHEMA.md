Documented experiment values are permitted and remain separate from suitable product defaults. Unknown facts must not be replaced with invented facts. Accepted G3 is an adjustable relative template, not a recovered original image size or validated all-video default. Final product identifier formats and configuration-version representation remain OPEN.

## Configuration consistency requirements

- Geometry, frames, bounding boxes, trajectory points, and the selected anchor must refer to a declared compatible coordinate system. Preprocessing/resizing must not silently shift the line or polygons.
- Polygon membership and signed line distance are independent; G3 retains the small shared-edge/line offset. Measurements still in the origin strip after a passage are not an origin return until a measured departure and return occur.
- Prototype geometry parameters must be supplied explicitly for each fixture/replay. Retain parameter meaning, effective native geometry, cache/geometry/helper hashes, source measurement links and processed scope; experiment settings are not accepted product defaults by implication.
- `GEOMETRY_TRANSITION` diagnostics retain `accepted_count_event=False` and `repeat_business_policy_open=True`; they do not define a `CountEvent`, vehicle category or physical traffic total.
- Detection, tracking, eligibility, and counting remain separate; the counting configuration cannot silently crop YOLO to side regions.
- Unknown detector/tracker/ReID capabilities must be verified rather than represented as supported settings. No missing asset, parameter, or category mapping may be silently substituted.
- Configuration and output must preserve video identity and effective settings for audit. No secret values belong in configuration examples or committed evidence.
- Phase 0 checked document consistency only. G3 feedback and [GEOMETRY_CONTRACT.md](GEOMETRY_CONTRACT.md) establish accepted geometry/qualitative rules; historical G2 remains conditional on its superseded assumption. The user now authorizes [PHASE_6_TASK.md](PHASE_6_TASK.md) with explicit [counting contract](COUNTING_CONTRACT.md). Original display reconstruction, all-video reliability, final taxonomy, automatic deduplication and suitable ReID configuration remain OPEN. Actual numerical/visual findings remain in separate phase reviews.
- A future Phase 11 setup page must let users configure the line and polygons, as reiterated in [default delegation](evidence/phase_5/feedback/G2_review_002.json). No product UI or executable UI schema is implemented in this revision.

## Phase 6 explicit experimental configuration

**ENGINEERING EXPERIMENT:** `contract_version="phase6_option_a_v0"`, `metric="passage"`, `review_policy="audit_gated"`, `neutral_band_px=0.0`, and `confirmation_observations=1` select the retained `b0_c1` diagnostic control. These numbers were not selected by the user and are not suitable production defaults. Helper/notebook paths and exact review payload are documented by [COUNTING_CONTRACT.md](COUNTING_CONTRACT.md).

`input_identity` binds `video_sha256`, `records_sha256`, `diagnostics_sha256`, `geometry_sha256`, `variant`, native `width`/`height`, and `parent_run_id`. `recording_metadata` carries known context; unknown store/location/day-type values are null, never inferred from filename. Semantic config identity hashes the supported policy/input/context fields; execution time/random labels are separate provenance. Candidate/review/event identities are layered, and category is excluded from physical-passage event identity.

Evidence path/hash/frame mappings, review conclusions and unit/passage grouping are explicit inputs preserved separately from machine decisions. Invalid review evidence cannot authorize a count. Duplicate members/returns remain inspectable; positive-duration overlapping same-unit passage intervals cannot be made independent merely by distinct labels. Aggregate snapshots count only unique accepted events on the selected config/review result, without summing across reruns or incompatible namespaces.

## Phase 6 Opsi B frozen experimental configuration

**IMPLEMENTED ENGINEERING EXPERIMENT:** [TOR3-PAGI_option_b_v1.json](evidence/phase_6/config/TOR3-PAGI_option_b_v1.json) uses `policy_version="phase6_option_b_v1"`, `metric="passage"`, `neutral_band_px=0.0` and `confirmation_observations=1`. G3/BC, finite segment, neutral boundaries and conservative gap/endpoint/prediction rules remain unchanged. Family changes and missing measured frames split every track into episodes before scope filtering; vehicle episodes establish their own measured origins. This creates new candidates, rather than promoting A's blocked histories.

`comparison_track_ids` and `scope.track_ids` select 13 discovered IDs. `scope.association_frame_windows` declares six inclusive windows: `[[0,80],[4975,4980],[5011,5030],[5116,5132],[6256,6260],[7712,7725]]`. Complete source episodes/raw conflict context are retained; scope limits relation feature evaluation and candidate crossing/confirmation selection, not episode extraction. This is a case comparison, not whole-video processing.

`association.component` explicitly requires common/consecutive support ≥3 frames, first BC inside motorcycle fraction ≥1.0, normalized center distance ≤0.51 and relative-motion residual ≤0.15. `association.same_vehicle` requires support ≥2 frames, IoU ≥0.59, normalized center distance ≤0.10 and residual ≤0.01. These controls are bound to [frozen_thresholds.json](evidence/phase_6/option_b_calibration/frozen_thresholds.json) by `calibration_evidence_path`/`calibration_evidence_sha256`; the notebook checks byte hash, source records and exact threshold equality. They are development-derived engineering controls, **not suitable product defaults**. The held-out component pair is excluded from their derivation; development and negative coverage limits remain explicit in [the task](PHASE_6_OPTION_B_TASK.md).

`identity_support_policy` requires the same frozen gates within each candidate's measured origin–confirmation window; an exploratory global relation cannot resolve an earlier passage. `grouping_enabled=False` defines the separately retained episode-only ablation with its own policy identity. Category unanimity uses full relevant vehicle episode/group observations, making B an offline experiment; it does not imply category availability at the confirmation frame. No appearance vectors or ID-specific resolver rules are supplied.

A original, A updated, ablation, B machine and B reviewed remain separate. Human case feedback is review reference, not an automatic feature; reviewed changes retain provenance without editing machine results. Namespace/source/episode/passage identities and accepted-only reconciliation prevent summing across controls/reruns. Suitable numeric defaults, global pickup/bus/angkot taxonomy, vehicle-ReID, online semantics and generalization remain OPEN. Actual runs and passage comparisons belong to [PHASE_6_OPTION_B_REVIEW.md](PHASE_6_OPTION_B_REVIEW.md).
