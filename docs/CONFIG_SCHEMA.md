# Preliminary Configuration Schema

Status: preliminary product schema established in Phase 0, complemented by the accepted [Phase 5 geometry contract](GEOMETRY_CONTRACT.md), versioned per-video geometry and implemented prototype helper/notebook. Prototype geometry parsing and synthetic validation exist; this is still not a finalized production configuration or `CountEvent` schema. Actual replay/configuration evidence and limits are reported in [PHASE_5_REVIEW.md](PHASE_5_REVIEW.md). Historical visual drafts retain their original statuses.

The product section/field names below remain **PROPOSAL** for a future finalized serialization format. The scoped prototype interfaces and mandatory geometry experiment parameters are explicit in [GEOMETRY_CONTRACT.md](GEOMETRY_CONTRACT.md). A confirmed value is a requirement/accepted scoped decision; an OPEN product value must not be silently selected. Documented experiment values are permitted and remain separate from suitable product defaults. Unknown facts must not be replaced with invented facts. Accepted G3 is an adjustable relative template, not a recovered original image size or validated all-video default. Final product identifier formats and configuration-version representation remain OPEN.

Read with [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md), [MODEL_SPEC.md](MODEL_SPEC.md), [COUNTING_LOGIC.md](COUNTING_LOGIC.md), [API_CONTRACT.md](API_CONTRACT.md), and [OPEN_DECISIONS.md](OPEN_DECISIONS.md).

| `geometry` | `side_a_polygon`, `counting_line`, `side_b_polygon` | CONFIRMED [accepted G3](evidence/phase_5/accepted_geometry/TOR3-PAGI-G3.json): template line `(4.5,516.5)` to `(936.4,305.4)`; A labels P1A `(4.5,516.5)`, P1B `(4.5,348.2)`, P1C `(936.6,305.8)`, P1D `(557.5,165.3)` with simple perimeter A→B→D→C. Filtered `bbox`, stored `center`, predicted/lifecycle positions do not substitute. Universal superiority/physical road contact remains unproved. |

| `geometry` | `confirmation_observations` | REQUIRED explicit prototype experiment input: positive integer of consecutive measured opposite-ROI observations outside the band. No implicit suitable product default. Interrupted qualifying arrival resets the consecutive confirmation evidence. |

## Configuration consistency requirements

- Geometry, frames, bounding boxes, trajectory points, and the selected anchor must refer to a declared compatible coordinate system. Preprocessing/resizing must not silently shift the line or polygons.
- Polygon membership and signed line distance are independent; G3 retains the small shared-edge/line offset. Measurements still in the origin strip after a passage are not an origin return until a measured departure and return occur.
- Prototype geometry parameters must be supplied explicitly for each fixture/replay. Retain parameter meaning, effective native geometry, cache/geometry/helper hashes, source measurement links and processed scope; experiment settings are not accepted product defaults by implication.
- `GEOMETRY_TRANSITION` diagnostics retain `accepted_count_event=False` and `repeat_business_policy_open=True`; they do not define a `CountEvent`, vehicle category or physical traffic total.
- Detection, tracking, eligibility, and counting remain separate; the counting configuration cannot silently crop YOLO to side regions.
- Unknown detector/tracker/ReID capabilities must be verified rather than represented as supported settings. No missing asset, parameter, or category mapping may be silently substituted.
- Configuration and output must preserve video identity and effective settings for audit. No secret values belong in configuration examples or committed evidence.
- Phase 0 checked document consistency only. Latest [G3 feedback](evidence/phase_5/feedback/G3_review_001.json) accepts the template/B and labels unchanged A coordinates; the question and answer establish contextual acceptance of the qualitative rules recorded in [GEOMETRY_CONTRACT.md](GEOMETRY_CONTRACT.md). Synthetic validation precedes retained-track replay; actual findings and experiment limits are reported in [PHASE_5_REVIEW.md](PHASE_5_REVIEW.md). Historical G2 placement remains conditional on its superseded assumption. Original display size/crop and all-video reliability remain UNKNOWN; final category, deduplication and suitable ReID configuration remain OPEN.
- A future Phase 11 setup page must let users configure the line and polygons, as reiterated in [default delegation](evidence/phase_5/feedback/G2_review_002.json). No product UI or executable UI schema is implemented in this revision.
